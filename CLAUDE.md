- Fachlogik in `src/katalog`, `src/modell`, `src/netz`, `src/pruefung`, `src/speicher` ohne React und vollständig getestet; Oberfläche in `src/ui`.
- Vor jedem Commit: `npm run lint`, `npm test`, `npm run build` und `npm run e2e` (lokal mit Edge auf Port 4181; 4173 gehört dem Prozesslotsen, mehrere Apps laufen parallel). Bei Änderungen an `src-tauri`, `src/plattform` oder am Ablauf zusätzlich `cargo test` (in `src-tauri`) und `npm run desktop:test`. Die CI prüft Lint, Unit-Tests und Build, `windows.yml` bei Änderungen am Programmteil Programm und Installer. Läuft schon ein Server auf 4181, nutzt Playwright ihn ohne neuen Build; dann vorher `npm run build`.
- Normtext: Die DIN SPEC 27076 ist urheberrechtlich geschützt. Keine Leitfragen, Anforderungs- oder Empfehlungstexte aus der Norm übernehmen, nur eigene Formulierungen. Die PDF liegt nur lokal in `normen/` (steht in `.gitignore`). „CyberRisikoCheck“ nicht als Namen verwenden.
- Keine Live-Abfragen fremder Domains in Tests: DNS- und Website-Prüfungen nur mit aufgezeichneten oder nachgebildeten Antworten (`src/netz/testnetz.ts`, `testdaten/`; Browsertests fangen DoH mit `page.route` ab). Ablauf- und Browsertests nutzen `example.com`. `scripts/fixtures-aufnehmen.mjs` fragt live ab und wird nur von Robin von Hand gestartet.
- Windows-Programm (ab Phase 5): Installer nur auf Robins ausdrücklichen Wunsch auf seinem Rechner ausführen (am 11.11.2026 gewünscht: installiert pro Benutzer mit Desktop-Verknüpfung); Testläufe mit `npm run desktop:test` (Debug-Build ohne Installation; legt die Programmdaten vorher beiseite und stellt sie danach wieder her, bricht ab, solange der Sicherheitscheck läuft). `src-tauri/windows/installer-test.ps1` deinstalliert am Ende und läuft deshalb nur in der CI.
- Rust: `cargo` liegt in `/c/Users/Robin/.cargo/bin` (nicht im PATH). Lokal mit `CARGO_TARGET_DIR=C:/Users/Robin/AppData/Local/cargo-ziel` bauen (gemeinsamer Zwischenspeicher mehrerer Apps; cargo wartet bei Sperre, das ist gewollt). Debug-Build: `npx tauri build --debug --no-bundle`, Installer: `npx tauri build`.
- Zahlen in der README zum Beispielbetrieb sind durch Tests abgesichert (`src/modell/beispiel.test.ts`); bei Änderungen am Beispiel beide anpassen.
